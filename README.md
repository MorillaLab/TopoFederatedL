> **Correction notice (v2.0.0).** The numerical results shown in earlier versions of this README and in
> version 1 of the preprint (arXiv:2603.04323v1) were **not produced by running this code** and are
> **withdrawn**. Version 2.0.0 is a corrected implementation. Every number in the revised manuscript is
> regenerated by a single script, `ptopofl_v2.py`, with fixed seeds. The v1.0.0 code remains available
> under the git tag `v1.0.0` for transparency only.

**pTopoFL** is a clustered, personalised federated-learning method.
1. Each client computes **once** a compact persistent-homology (PH) descriptor of its feature distribution.
2. The server uses these descriptors to group clients and to weight them within groups.
3. Training uses a blended, clustered form of local gradient descent and returns one personalised model per group.

## Protocol

<p align="center">
  <picture>
    <source media="(prefers-color-scheme: dark)" srcset="assets/ptopofl_protocol_dark.svg">
    <img src="assets/ptopofl_protocol_light.svg" width="100%"
         alt="pTopoFL protocol. Round 0, once: each client computes a 46-dimensional persistent-homology descriptor of its feature cloud and sends it to the server, which builds a partition of the clients, trust scores, weights and cluster masses. Every round: the server sends each client the model of its cluster; the client runs tau local gradient steps and sends back its model; the server forms per-cluster weighted sums (compatible with secure aggregation) and blends them with the consensus.">
  </picture>
</p>

Each client sends its descriptor **once**, before training (green). In every round it receives
the model of its cluster (dashed blue) and returns its locally updated model (solid blue). The
server uses the descriptors only to fix the partition and the weights. It uses the models only
through per-cluster weighted sums.

**Scope.** pTopoFL sends model parameters every round, exactly like FedAvg, so it is **not a privacy
mechanism**.
- It works with secure aggregation, because the server only needs per-cluster sums.
- It works with record-level differential privacy; the paper gives the full (ε, δ) accounting.
- The descriptor itself reveals population-level properties of a client's data.

## What changed in v2.0.0

| v1.0.0 | v2.0.0 |
|---|---|
| Local models re-solved to convergence every round (training effectively one-shot) | τ local gradient steps per round |
| Personalised models computed but discarded; only the global model was evaluated | Personalised cluster models broadcast to clients and evaluated per client |
| Descriptor re-subsampled every round; 48 coordinates, two of them duplicated | Descriptor computed once (fixed seed, averaged over 5 subsamples); 46 distinct coordinates |
| Blending coefficient α used at face value | α calibrated from a target effective blending (closed-form result) |
| Mean/std anomaly score | Robust median/MAD score; trust-weighted cluster masses |
| Simplified surrogates of the baselines | FedProx, SCAFFOLD, pFedMe, Ditto and IFCA as published, plus a PACFL-style subspace baseline |
| Linearly separable synthetic data (AUC = 1 for every method) | Non-trivial synthetic federations, plus real four-hospital data (Fed-Heart-Disease) |

## Key findings of the revised manuscript

- **Theory** (strongly convex, smooth losses). One round of the complete procedure (clustering,
  weighting and blending) is a (1−ημ)^τ-contraction for any partition. The fixed point is
  characterised explicitly: local-step drift, exact effective blending, and a stochastic floor.
  Personalisation lowers the error floor in proportion to a measurable between-cluster share of the
  dispersion of client optima.
- **When feature geometry and decision rules co-vary**, the PH partition recovers the latent client
  groups, including tail-based differences that a linear-subspace descriptor misses. pTopoFL is then
  competitive with the strongest clustered baselines.
- **When heterogeneity is invisible in feature geometry** (concept or label shift), pTopoFL offers no
  advantage over FedAvg; loss-based methods such as IFCA or Ditto are preferable.
- **Two negative results.** Descriptor-based anomaly detection is weak, and privatising the descriptor
  under its provable sensitivity destroys the partition.

All numbers are in the paper. They are produced by the script below and deliberately not copied here.

## Installation

```bash
git clone https://github.com/MorillaLab/TopoFederatedL
cd TopoFederatedL
pip install -r requirements.txt
```
Ripser is optional and is used for fast H₁. Without it, a pure-NumPy boundary-matrix reduction with
identical output is used, which is slower.

## Reproducing every result

```bash
python ptopofl_v2.py --exp all --seeds 10 --out results_v2              # all experiments, ~15-20 min on CPU
python ptopofl_v2.py --exp all --quick --no-heart --out results_quick   # smoke test, a few minutes
python ptopofl_v2.py --exp main,alignment --seeds 10                     # selected experiments
```
Available experiments: `theory`, `main`, `alignment`, `robust`, `privacy`, `ablation`, `sensitivity`,
`continual`, `cost`.

| Output | Content |
|---|---|
| `results_v2/tables/*.tex` | LaTeX tables included by the manuscript |
| `results_v2/tables/results_macros.tex` | every number quoted in the text, as `\newcommand` macros |
| `results_v2/figures/*.pdf, *.png` | all figures |
| `results_v2/json/*.json` | raw per-seed results |

**Real data.** The four UCI heart-disease files are downloaded automatically, and the script prints the
site sizes after preprocessing. Without internet access, place
`processed.{cleveland,hungarian,switzerland,va}.data` in `heart_data/`.

**Google Colab.** Open [`notebooks/ptopofl_v2_colab.ipynb`](notebooks/ptopofl_v2_colab.ipynb)
(badge above). It installs Ripser, runs the tests and all experiments, checks the site sizes
and downloads the outputs.

**Make targets.** `make test`, `make quick`, `make all` and `make paper`.

## Tests

```bash
pip install pytest
pytest -q tests
```
The tests check the implementation (descriptor dimension and invariances, agreement of the two
H₁ backends, data loader). They also check the main theoretical results on the actual code:
- one round is a contraction (Theorem 3);
- the drift bias stays below its bound (Theorem 4), and FedAvg with one local step is exact;
- the blending calibration (Proposition 5) and the dispersion decomposition (Proposition 6);
- partition stability (Theorem 9) and the trust-score cap (Proposition 12);
- the DP accounting (Proposition 2);
- SCAFFOLD reaches the global optimum.

They run on every push, on Python 3.9, 3.11 and 3.12.

## Using the components

```python
import ptopofl_v2 as P

raw = P.make_synthetic("aligned", K=8, seed=0, shift=1.0)   # or: P.make_heart(seed=0)
clients, eta, n = P.build(raw)                               # L2-regularised logistic clients
models, history, info = P.ptopofl_fit(clients, eta, n, seed=0, T=150, tau=10, ev=50)
print(P.evaluate(clients, models))   # personalised log-loss, AUC, balanced accuracy
print(info["labels"], info["alpha"]) # descriptor partition and calibrated blending coefficient
```
All hyper-parameters are in `P.CFG`, the single source of truth for the paper's table.

## Descriptor layout (46 coordinates)

```
Index    Component
0-19     H0 Betti curve (20 thresholds)
20-39    H1 Betti curve (20 thresholds)
40, 41   N0, N1   number of finite pairs with positive persistence
42, 43   E0, E1   persistence entropy
44, 45   A0, A1   l2 amplitude
```
